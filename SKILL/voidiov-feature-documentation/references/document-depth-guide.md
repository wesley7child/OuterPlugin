# 功能文档深度指南

## 什么时候需要 A 级文档

出现任一条件就按 A 级处理：跨项目调用、认证或会话、权限、数据库写入、外部 HTTP、Socket/消息、定时任务、启动同步、并发/租约、缓存一致性、敏感数据、迁移/发布/回滚或用户可见状态收敛。

## A 级文档的最小闭环

```text
入口/触发
  -> 输入与前置条件
  -> 校验与归一化
  -> Application/Domain 编排
  -> 数据库/外部系统
  -> 响应或异步结果
  -> 状态/副作用
  -> 失败分类与恢复
  -> 验收和证据
```

每个箭头都要能定位到真实文件、类、方法、配置键、表/索引或测试命令。不能定位的内容标记为“待核查”或“部署待验证”。

## 设计与实现双栏思路

推荐在同一文档中使用两个小节或表格：

| 项目 | 设计契约 | 当前实现 |
| --- | --- | --- |
| 触发/入口 | 应由谁在什么条件下触发 | 当前实际入口和调用方 |
| 状态 | 允许的状态和转换 | 代码实际写入/读取的状态 |
| 失败 | 应如何分类、重试和降级 | 当前异常映射、日志和回滚行为 |
| 数据 | 需要的表、字段、索引 | 当前 SQL、Mapper 和写入时机 |
| 验收 | 可执行的通过条件 | 已执行结果或待验证项 |

新功能在编码前允许“当前实现”为“待实现”；存量功能不能用设计契约替代源码事实。

## 故障决策表

复杂功能至少写一张表，避免只写“失败返回错误”：

| 故障类别 | 示例 | 是否写业务状态 | 是否回滚主事务 | 是否可重试 | 用户/运维下一步 |
| --- | --- | --- | --- | --- | --- |
| 输入错误 | 缺字段、越界、格式错误 | 否 | 无 | 修正后重试 | 修正输入 |
| 业务冲突 | 重复、状态不允许、唯一键竞争 | 通常否 | 是/按实现 | 查询最新状态后决定 | 刷新并重新提交 |
| 权限拒绝 | 未登录、无权限、内部来源不可信 | 否 | 无 | 否 | 重新授权或走正确入口 |
| 上游完整错误 | 4xx/5xx、合法错误响应 | 按功能 | 按实现 | 仅幂等读请求 | 检查上游和凭据 |
| 本地传输失败 | 连接、超时、响应体中断 | 按功能 | 按实现 | 有界重试 | 等待下一轮或人工重试 |
| 本地持久化失败 | DB/事务/租约/事件失败 | 不得伪造成功 | 回滚或补偿 | 按幂等性 | 查日志和数据一致性 |

按功能实际情况删减行，但不能只保留“成功/失败”两类。

## 可读性检查

- 用户只看前两节，应能完成一次操作并知道失败处理。
- 开发者只看调用链、状态/故障表、代码定位和证据矩阵，应能找到修改入口和验证命令。
- 索引只承担导航，不复制正文；规则文件只承担通用约束，不替代功能事实。
- 文档长是因为分支多、契约复杂，而不是因为复制源码、重复背景或堆积历史流水账。
