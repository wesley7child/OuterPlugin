# VOIDIOV 功能文档审查清单

## 范围与事实

- [ ] 已阅读根目录和相关子项目 `AGENTS.md`。
- [ ] 已检查现有 README、专题文档和索引，避免重复或冲突。
- [ ] 已确认涉及项目、责任边界和调用链。
- [ ] 已从控制器、路由、菜单、定时任务、消息/Socket、配置开关和数据库用例盘点功能点，没有只按模块名猜测。
- [ ] 每个可独立操作、调用、配置或验收的功能都有独立 Markdown，或在索引中明确归入紧密相关功能。
- [ ] 文档中的路径、字段、状态、权限、配置和测试结论都有代码或配置证据。
- [ ] 未把推测、未来计划或未执行的测试写成当前事实。
- [ ] 关键结论已标注 `[源码]`、`[配置]`、`[SQL]`、`[测试]` 或 `[部署待验证]`。

## 关键契约

- [ ] 目标和非目标清楚，范围没有无意扩大。
- [ ] API/事件的路径、方法、入参、出参、权限和错误语义完整。
- [ ] DTO、Entity、配置、数据库和索引的变化已说明。
- [ ] Request/Response 已列出类型、必填、默认值、范围、归一化和兼容规则。
- [ ] 状态机已列出触发条件、下一状态和副作用。
- [ ] 数据库变更明确标出人工 SQL；没有设计自动迁移。
- [ ] 事务边界、唯一键/乐观锁、重复提交、竞态和多实例行为已说明（适用时）。
- [ ] 超时、重试、并发、幂等、缓存、版本保护和资源上限已覆盖（适用时）。
- [ ] 敏感信息、日志、鉴权、代理和跨服务信任边界已覆盖。
- [ ] 空值、重复、越界、下游失败、重启恢复和兼容性边界已覆盖（适用时）。
- [ ] 已写出用户前置条件、操作步骤、成功结果和常见失败处理。
- [ ] 已写出入口到结果的真实代码链路，并定位到关键类、方法、配置和持久化对象。

## 精炼程度

- [ ] 每一节都回答一个明确问题。
- [ ] 优先使用表格和短列表，没有大段重复源码或规则全文。
- [ ] 删除不影响实现、维护、验证或安全判断的细节。
- [ ] 当前契约、历史方案、后续事项分开。
- [ ] 文档读完后，人可以知道“改什么、为什么、影响谁、如何验收”。
- [ ] 用户操作章节和开发实现章节分层，既能作为用户手册又不会把源码整段复制进去。
- [ ] 文档没有把项目概览、模块清单或 API 列表冒充功能实现说明。

## 收口与验证

- [ ] 顶部状态与实际证据一致。
- [ ] 已实现、已验证、待验证和未实现明确分开。
- [ ] 验收项可执行，且记录了命令或真实环境验证结果。
- [ ] 代码、配置、SQL、README 和文档索引没有明显不一致。
- [ ] 项目根目录 `doc/文档索引-readme.md` 已列出功能清单、状态、入口、文档链接和最后核查日期。
- [ ] `doc/` 下每个 Markdown 文件名同时包含中文和英文，并采用 `中文名称-english-name.md` 的稳定格式。
- [ ] 变更记录只保留有长期价值的设计或状态变化。
- [ ] `已实现`、`已验证`、`待验证`、`未实现`彼此分开，且验证结论附有命令或环境证据。
